# Massive News 수집 결과 분석

- 수집일: 2026-10-12 (UTC, 실행 로그 기준)
- 분석 대상: `data/raw/massive_news_ticker/`의 티커별 연도 JSONL, 상태 파일 및 실행 로그
- 엔드포인트: `GET https://api.massive.com/v2/reference/news`
- 요청 구간: `2016-06-22T00:00:00Z` 이상, `2026-10-11T00:00:00Z` 미만
- 대상 티커: NVDA, AMD, TSM, MU, SNDK, MPWR, VICR, ADI, ON (9개)
- 수집 코드: `src/capstone/data/massive_news.py`, `scripts/fetch_massive_news.py`
- 테스트: `tests/data/test_massive_news.py`
- 로컬 산출물: `data/raw/massive_news_ticker/` (Git ignore 대상, 커밋하지 않음)

## 1. 요약

- 9개 티커 폴더에 **44,214개 기사 행**을 저장했다. 티커별 JSONL 행 수 합계와 실행 로그의 신규 저장 기사 수가 일치한다.
- API 요청 50회가 모두 성공했다. 재시도, 429 응답, 서버 오류, 연결 오류는 없었고 실행 시간은 **588.9초(약 9분 49초)**였다.
- 57개 연도 JSONL 파일에서 44,214행을 확인했다. JSON 오류, 티커별 ID 중복, 발행 연도와 파일명 불일치, `tickers` 태그 불일치는 발견되지 않았다.
- 서로 다른 티커 폴더 사이에는 같은 기사 ID가 반복된다. 전체 44,214행의 전역 고유 ID는 **35,292개**다.
- NVDA가 전체 티커별 행의 약 **56.2%**를 차지한다. 티커별 기사 수와 연도별 분포가 균등하지 않다.
- 요청은 2016년부터 시작하지만 관측 데이터는 **2018-11-05 ~ 2026-10-10**에 분포한다. 2016~2017년 파일은 없으며, 데이터 공백만으로 해당 기간에 기사가 없었다고 결론 내릴 수는 없다.

| `image_url` | 44,131 | 99.8% |

## 5. ID 중복과 티커 태그

- 각 티커 폴더 내부 ID 중복은 **0행**이다.
- 전체 44,214행의 전역 고유 ID는 **35,292개**다.
- **7,224개 ID**가 둘 이상의 티커 폴더에 나타난다. 고유 ID를 초과하는 반복 행은 8,922개다.
- 모든 행의 `tickers` 배열에 저장 폴더의 티커가 포함되어 있다.
- 데이터를 월별 , 연도별, ticker별 전체 기간에 대해 수집하고 [2016-06-22, 20206-10-05] 기간 데이터를 비교한 결과, 티커별 기사 ID와 전체 JSON 내용이 모두 같았으며, 중복 ID도 발견되지 않았다.

티커별 JSONL은 종목 단위 분석에 적합하지만, 여러 티커 파일을 합치면 같은 기사가 반복 집계된다. 전역 기사 테이블을 만들 때는 ID 기준으로 기사 레코드를 통합하고 티커 연결 정보를 보존해야 한다.

## 6. 데이터 검사와 한계

- 57개 JSONL 파일의 44,214행에서 JSON 파싱 오류는 0건이었다.
- ID, `published_utc`, `title`, `author`, `article_url`, `publisher`, `tickers` 누락은 0건이었다.
- `published_utc`를 UTC로 변환한 연도와 저장 파일명의 연도가 다른 행은 0건이었다.
- JSONL에 기록된 티커와 티커 폴더가 맞지 않는 행은 0건이었다.
- 요청 시작은 2016년이지만 2016~2017년 데이터는 없다. 첫 관측 기사는 2018년이며, 대다수 데이터는 2021년 이후다. 이 분포만으로 원인을 확정하거나 해당 기간에 API 제공 기사가 전혀 없었다고 판단할 수 없다.
- 기사 행 수가 티커별로 크게 다르다. NVDA가 24,831행으로 가장 많고, VICR는 189행으로 가장 적다. 기사량이 적은 종목은 일 단위 텍스트 피처가 희소할 수 있다.
- SNDK 관측 데이터는 2025년부터 시작한다. 과거 구간에 기록이 없다는 점을 종목 이력이나 공급자 범위와 대조하기 전에는 원인을 단정하지 않는다.
- `published_utc` 형식과 저장 연도는 확인했지만, 최초 공개 시각의 정확성이나 거래 시점에 실제 이용 가능했는지는 별도 검증이 필요하다. 장 마감 이후 및 휴장일 기사 처리도 거래 캘린더를 기준으로 정해야 한다.
- `description`, `keywords`, `insights`는 원문 전체와 동일하지 않다. 필드가 비어 있는 경우를 중립 감성이나 뉴스 부재로 간주하면 안 된다.
- 무료 Basic Plan에서는 분당 요청 횟수가 5회로 제한되므로, 요청 간 12초의 간격을 두고 데이터를 수집하였다. 이에 따라 월별 데이터 수집에는 3시간 이상, 연도별 데이터 수집에는 약 25분, ticker별 전체 기간 데이터 수집에는 약 10분이 소요되었다.
- 모든 수집 방식에서 데이터 수집이 시작된 이후에는 중단이나 오류 없이 전 과정을 완료하였다.

## 7. 재현 범위

이 보고서는 사용자가 제공한 터미널 실행 요약과 2026-10-12 UTC 실행 로그, 현재 `data/raw/massive_news_ticker/`의 JSONL 및 상태 파일을 대조한 결과다. 터미널 통계의 44,214 신규 기사 행은 로컬 JSONL 행 수 합계와 일치한다. 원본 응답 전체나 Massive 측 전체 기사와의 대조는 수행하지 않았다.

원본 JSONL, 상태 파일 및 실행 로그는 로컬 데이터 산출물이며 Git에 커밋하지 않는다.

## 8. 참고 사항

- Massive는 Benzinga로부터 뉴스 데이터를 제공받는다.
- Massive 공식 문서에 따르면 데이터 업데이트 주기는 1시간이다.
- Massive 공식 문서에 따르면 Basic Plan에서는 현재 시점으로부터 2년 이내의 데이터에 접근할 수 있다. 다만, 직접 요청을 
  테스트한 결과 2016-06-22 데이터부터 요청이 가능했으며, 실제 수집에서 확인된 가장 이른 데이터는 NVDA의 2018-11-05 22:50:00 데이터였다.
- CLI 명령에 --start 파라미터를 지정하지 않으면, 티커별 상태 파일에 기록된 마지막 수집 성공 시점의 종료 일시를 기준으로 수집을 이어간다. 이를 통해 이전 수집 작업에 이어 데이터를 수집할 수 있다.
- 공식 문서에 명시된 데이터 업데이트 주기를 고려할 때, --end 파라미터를 지정하지 않으면 종료 시점은 기본적으로 현재 
  시각보다 1시간 이전으로 설정된다.
